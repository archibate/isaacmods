- With ArriveAtDoor on, a trip now lands at the walk's door on the first visit to a room too, and after a quit-and-continue. The door to stand at was looked up in what the mod had learned by standing in rooms, and from next door it had only learned that a passage exists, not which door is on the far side; a continue threw the whole record away besides. With nothing to aim at, the game's own landing stood, and the game puts you at the wall facing the room you left, by whichever of the two grid distances is larger — right only when the walk was straight. The door is now read off the map itself: the side the walk steps in by names the wall, and where the entered cell sits in a big room names which of that wall's two doors. (thank @Moe&OF for the report, and for the three-step recipe that pinned it: wrong, right after entering once, wrong again after a continue!)
- Arriving at the door a walk would have come in by is off by default now, under a new name (MCM: ArriveAtDoor). It had been on for everyone since 08-29, and both of this week's reports trace to it: a far trip into a room bigger than the screen can only arrive at the right wall by passing through the last room on the way first, and that room is on screen for a moment before the fade — read as the view twitching, or as landing in an empty room and going straight on into the next. Few asked for the door landing and more minded the pass-through, so it is now the choice of whoever wants it. The switch is renamed because every save already holds the old one on, and a new default must not lose to that. (thank @li3397450972 and @Whitor_大白 for the reports!)
- The mod is being taken apart into modules, and this is the first release built that way. Until last week the whole thing was one file of 2400 lines; it is now ten, one each for the settings, the settings menu, the floor, the trip rules, the trip itself, the map window, the cursor on the game's own map, and the input loop, with the old file left as the part that wires them together. Nothing about how it plays is meant to change and every path was walked in game before this went out, but a move this size can still knock something loose where nobody thought to look. So if something that worked last week has stopped working, please say so in the comments: which version it broke in, and what you were doing when it did, is enough to find it.
- gtconfig.lua is now read with the game's own include instead of require. Two things follow. A `luamod goodtripfixed` picks up an edit to that file at once, where before the first read was kept for the whole game session. And the file can no longer be shadowed: require looks through every mod's folder for a file of that name, and the original GoodTrip ships a gtconfig.lua too, so with both installed the fixed mod could load the old one and silently skip every pin. include only ever reads from this mod's folder.
